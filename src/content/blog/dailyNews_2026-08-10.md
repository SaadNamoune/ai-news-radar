### [LaFaCt: Latent Geometry-Based Misinformation Detection via Activation Engineering](https://arxiv.org/abs/2608.06417)

<small>**cs.LG updates on arXiv.org** &nbsp;·&nbsp; 2026-08-10 05:00:00 &nbsp;·&nbsp; `misinformation-detection` `activation-engineering` `transformer-latent-space`</small>

**Overview:** This paper introduces LaFaCt, a novel misinformation detection framework that treats truthfulness as a geometric property in a transformer's latent space. It addresses limitations of traditional methods by avoiding fine-tuning, external knowledge retrieval, or task-specific supervision. **Method:** The approach uses Contrastive Activation Addition (CAA) to derive a misinformation direction in the residual stream by contrasting activations from truthful and false statements. At inference, the last-token activation of an unseen claim is projected onto this direction and classified via an MLP. **Results:** Evaluated on 11 models (270M–12B parameters) across AVeriTeC, LIAR, and FACTors benchmarks, the method matches or surpasses zero-shot/few-shot prompting baselines on LIAR and FACTors, with larger gains for smaller models. Performance on AVeriTeC is limited due to its evidence-grounded labeling. **Impact:** Demonstrates that truthfulness is linearly separable in latent space, enabling interpretable, retrieval-free misinformation detection. Open-source code is available.

### [ACIF: Adversarial Causal Intervention Falsification for Generative Causal Models](https://arxiv.org/abs/2608.06427)

<small>**cs.LG updates on arXiv.org** &nbsp;·&nbsp; 2026-08-10 05:00:00 &nbsp;·&nbsp; `causal-inference` `adversarial-learning` `structural-causal-models`</small>

**Overview:** This paper introduces ACIF, a framework to falsify generative causal models by testing their interventional distributions. **Method:** A structural causal generator proposes observational/interventional distributions, while an adversarial experimentalist selects interventions to maximally falsify the generator. The discriminator evaluates observational fit, interventional equivalence, and point identification. **Results:** For finite model/intervention classes, the framework proves: (i) reduction to worst-intervention integral probability metrics; (ii) identification up to interventional equivalence; (iii) existence of mixed-strategy equilibria; (iv) finite-sample guarantees; and (v) logarithmic elimination under balanced-separation. A linear-Gaussian example shows observational indistinguishability resolved by a single intervention. **Impact:** Clarifies what adversarial causal discriminators can certify, bridging causal generative modeling, active discovery, and experimental design with theoretical guarantees.

### [Fairis: Robust and Group-Fair Collaborative Learning with Adversarial Fairness Poisoning Defense](https://arxiv.org/abs/2608.06469)

<small>**cs.CR updates on arXiv.org** &nbsp;·&nbsp; 2026-08-10 05:00:00 &nbsp;·&nbsp; `fairness-aware-aggregation` `collaborative-learning` `adversarial-robustness` `group-fairness`</small>

**Overview:** Fairis presents a server-side reweighting scheme to ensure group fairness and robustness against adversarial manipulation in collaborative machine learning. It addresses fairness poisoning, where adversaries evade accuracy-based defenses while maximizing group disparity. **Method:** Fairis computes client weights as ωₖ = η̄ₖ / Σⱼ η̄ⱼ, where η̄ₖ = η − Fₖ, Fₖ is the local Equal Opportunity Difference, and η > 1 is a security parameter. The method proves Monotone Weight Reduction (MWR), Demographic Participation, and Non-Gamesmanship, and extends MWR to colluding minority coalitions. **Results:** Fairis reduces an adversary's weight by 41–54% below a size-blind control on Taiwan Credit while maintaining 0.04 accuracy of benign performance. Against stealthy adversaries, Fairis outperforms clipped FairFed, which can zero a client outright. **Impact:** Provides the first provable defense against fairness poisoning, advancing secure and fair collaborative learning.

**Overview:** CyberForge introduces a framework to synthesize executable, repository-level security training data by injecting vulnerabilities into real C/C++ projects. ### [Cascade: Latency-Budget-Aware LLM Serving with Joint Scheduling and KV-Cache Management](https://arxiv.org/abs/2608.06557)

<small>**cs.DC updates on arXiv.org** &nbsp;·&nbsp; 2026-08-10 05:00:00 &nbsp;·&nbsp; `LLM-serving` `scheduling` `KV-cache` `service-level-objectives`</small>

**Overview:** LLM serving platforms struggle with heterogeneous request latencies under fixed service-level objectives (SLOs). This paper introduces *Cascade*, a system that computes per-request *latency budgets* (SLO minus predicted service time) to jointly optimize scheduling and KV-cache management. **Method:** Cascade estimates budgets using request characteristics, KV-cache state, and system load. Its scheduler prioritizes requests with tight budgets, while its memory manager uses the same budget to decide whether to restore, prefetch, retain, or recompute non-resident KV state. **Results:** On production traces across three LLMs, Cascade improves SLO-satisfied goodput by up to 2.4x and reduces SLO violations by 40% compared to vLLM’s FCFS scheduler. **Impact:** This work advances LLM serving by unifying scheduling and memory management under a single latency-aware framework, addressing heterogeneity in request costs and cache states while preserving fairness.

### [High-Precision Matrix Multiplication on FP4 Tensor Cores via Ozaki Schemes](https://arxiv.org/abs/2608.06812)

<small>**cs.DC updates on arXiv.org** &nbsp;·&nbsp; 2026-08-10 05:00:00 &nbsp;·&nbsp; `matrix-multiplication` `FP4-Tensor-Cores` `Ozaki-schemes` `mixed-precision`</small>

**Overview:** This paper enables FP64-equivalent matrix multiplication (DGEMM) on FP4 Tensor Cores by leveraging Ozaki schemes I and II, which decompose high-precision operations into low-precision computations. **Method:** The key insight is that FP4 values (E2M1) can be treated as integers when doubled, and shifting these integers by multiples of 13 covers all integers. This allows error-free intermediate sums in FP32 accumulators, enabling FP4-based Ozaki schemes. The paper also proposes kernel optimizations to boost attained performance. **Results:** On an RTX PRO 6000 Blackwell, the FP4-based Ozaki scheme II achieves performance competitive with an FP8 implementation and exceeds it at large problem sizes (e.g., 16384³). **Impact:** This work unlocks FP4 Tensor Cores for high-precision workloads, offering a path to faster DGEMM by exploiting their higher throughput compared to FP8, with implications for scientific computing and deep learning acceleration.

### [LivePlan: Real-Time Behavioral Correction for Long-Horizon GitHub Issue Resolution](https://arxiv.org/abs/2608.06701)

**Overview:** This paper introduces **LivePlan**, a framework to monitor and correct inefficiencies in long-horizon GitHub issue resolution by autonomous agents. The approach addresses challenges like plan drift, repeated failures, and premature termination in multi-step repair tasks. **Method:** LivePlan decouples judging and advising: a deterministic rule-based monitor detects behavioral inefficiencies (e.g., drift, repetition) without LLM invocation, triggering an advisor LLM only when corrections are needed. Implemented atop **SWE-agent**, it evaluates five LLMs (three executors, two advisors) on **SWE-bench Verified** and **SWE-bench Pro**. **Results:** LivePlan achieves up to 15.2% (average: 9.9%) higher issue resolution rates than vanilla SWE-agent, with minimal additional cost ($0.08 per instance). Gains concentrate on medium/hard instances, and new solutions emerge for previously unsolved problems. **Impact:** This work advances autonomous software engineering by reducing inefficiencies in long-horizon tasks, demonstrating scalable improvements in agent-based repair systems.

### [Large-Scale Empirical Study on the Energy Impact of Refactoring in Java](https://arxiv.org/abs/2608.06620)

<small>**cs.SE updates on arXiv.org** &nbsp;·&nbsp; 2026-08-10 05:00:00 &nbsp;·&nbsp; `software-refactoring` `energy-efficiency` `empirical-study` `Java`</small>

**Overview:** This study investigates the energy impact of refactoring in Java, challenging the assumption that behavior-preserving changes are energy-neutral. The authors conduct the first large-scale empirical analysis across two benchmarks: a **Micro-benchmark** (68 refactoring types under diverse workloads) and a **Practical-benchmark** (481 real-world refactoring commits). **Method:** Using repeated paired energy measurements, the study examines workload sensitivity, refactoring patterns, and explanatory factors. Metric- and LLM-based regression identification methods are evaluated for detecting energy regressions. **Results:** In the Micro-benchmark, 51.8% of refactoring-workload pairs show significant energy differences, with 45.3% of instances changing energy classification across workloads. In the Practical-benchmark, only 7.5% of commits show significant changes, though two-thirds differ by ≥10%. Execution time changes explain energy variation in controlled settings but weakly correlate in real-world commits. **Impact:** The findings highlight the need for workload-diverse evaluation and motivate new techniques for predicting refactoring-induced energy regressions, as existing methods are unreliable.

**Overview:** Cloudflare introduces a developer preview enabling automatic WebMCP (Web Model Context Protocol) support for any website via a single dashboard toggle, allowing browser-based AI agents to interact with web pages through structured tools instead of fragile HTML scraping or UI automation. This addresses inefficiencies in token consumption and brittleness in traditional automation. **Method:** WebMCP exposes machine-readable tools (e.g., `searchFlights`, `bookTicket`) via the `document.modelContext` API or declarative HTML annotations. Cloudflare’s implementation injects a `bridge.js` module at the edge using HTMLRewriter, composing tool packs (e.g., Content Credentials, Site MCP server) into a unified tool list. Static packs declare tools upfront, while dynamic packs discover tools at runtime. The bridge registers tools with `.registerTool` and proxies MCP tool execution via standard `execute()` and `CallToolResult` interfaces. **Results:** The preview targets Chrome 145+ and requires enabling via Cloudflare Dashboard’s Agent Readiness > Labs. Tool packs are selectable without redeployment, with plans to expand the library. **Impact:** Advances AI-agent interoperability with web content, reducing scraping overhead and UI fragility. Open questions include standardization maturity and cross-browser support.
